数据库索引类型全解析：从基础到高级优化技巧

索引是数据库优化中最核心的技术之一，正确的索引设计可以提升查询性能几个数量级。本文将全面解析MySQL中七种主要的索引类型，帮助你构建高性能的数据库系统。

1. 主键索引 (PRIMARY KEY)

定义与特性

主键索引是表中唯一标识每条记录的索引，每个表只能有一个主键索引。

-- 创建主键索引的两种方式
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100)
);

-- 或者使用独立约束
CREATE TABLE users (
    id INT AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100),
    PRIMARY KEY (id)
);

核心特点

  • 唯一性：主键值必须唯一且不能为NULL
  • 聚簇索引：InnoDB中，主键索引就是聚簇索引，数据按主键顺序存储
  • 自动创建：定义主键时自动创建对应的索引

最佳实践

-- 推荐使用自增整型作为主键
CREATE TABLE orders (
    order_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    order_date DATETIME DEFAULT CURRENT_TIMESTAMP,
    customer_id INT,
    total_amount DECIMAL(10,2)
);

-- 对于分布式系统，考虑使用雪花算法等分布式ID

2. 唯一索引 (UNIQUE INDEX)

定义与特性

唯一索引保证索引列的值必须唯一，但允许NULL值（除非列被定义为NOT NULL）。

-- 创建唯一索引
CREATE TABLE employees (
    id INT PRIMARY KEY,
    employee_code VARCHAR(20) UNIQUE,
    email VARCHAR(100) UNIQUE,
    department_id INT
);

-- 添加唯一索引
ALTER TABLE employees ADD UNIQUE INDEX idx_employee_code (employee_code);

使用场景

  • 业务唯一约束（如邮箱、手机号、身份证号）
  • 防止数据重复插入

注意事项

-- 唯一索引对NULL值的处理
INSERT INTO employees (id, employee_code, email) 
VALUES (1, 'EMP001', NULL);  -- 成功

INSERT INTO employees (id, employee_code, email) 
VALUES (2, 'EMP002', NULL);  -- 成功，因为NULL不等于NULL

-- 但如果是多列唯一索引，情况会不同
ALTER TABLE employees ADD UNIQUE INDEX idx_dept_code (department_id, employee_code);

3. 普通索引 (INDEX/KEY)

定义与特性

最基本的索引类型，没有唯一性约束，主要用于加速查询。

-- 创建普通索引
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(200),
    category_id INT,
    price DECIMAL(10,2),
    INDEX idx_category (category_id),
    INDEX idx_price (price)
);

-- 后期添加索引
CREATE INDEX idx_product_name ON products(product_name);

使用场景

  • 经常用于WHERE条件的列
  • 用于JOIN操作的列
  • 用于排序和分组的列

性能优化示例

-- 没有索引的查询（全表扫描）
EXPLAIN SELECT * FROM products WHERE category_id = 5;

-- 有索引的查询（索引查找）
EXPLAIN SELECT * FROM products WHERE category_id = 5;

4. 全文索引 (FULLTEXT)

定义与特性

专门用于全文搜索的索引类型，支持自然语言搜索和布尔搜索。

-- 创建全文索引
CREATE TABLE articles (
    id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255),
    content TEXT,
    created_at DATETIME,
    FULLTEXT(title, content)
);

-- 添加全文索引
ALTER TABLE articles ADD FULLTEXT idx_fulltext_content (content);

全文搜索操作

-- 自然语言搜索
SELECT * FROM articles 
WHERE MATCH(title, content) AGAINST('数据库优化' IN NATURAL LANGUAGE MODE);

-- 布尔搜索
SELECT * FROM articles 
WHERE MATCH(title, content) AGAINST('+MySQL -Oracle' IN BOOLEAN MODE);

-- 查询相关性评分
SELECT id, title, MATCH(title, content) AGAINST('数据库') as relevance
FROM articles 
WHERE MATCH(title, content) AGAINST('数据库')
ORDER BY relevance DESC;

配置优化

-- 查看全文索引相关配置
SHOW VARIABLES LIKE 'ft_%';

-- 调整最小词长度（默认4）
-- 在my.cnf中设置：ft_min_word_len = 2

5. 空间索引 (SPATIAL)

定义与特性

用于地理空间数据的索引，支持GIS数据类型。

-- 创建空间索引
CREATE TABLE locations (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    coordinate POINT NOT NULL,
    SPATIAL INDEX idx_spatial (coordinate)
);

-- 插入空间数据
INSERT INTO locations (name, coordinate) 
VALUES ('公司总部', ST_GeomFromText('POINT(116.3974 39.9093)'));

空间查询示例

-- 查找指定范围内的点
SELECT name, ST_AsText(coordinate) 
FROM locations 
WHERE ST_Contains(ST_GeomFromText('POLYGON((116.3 39.9, 116.5 39.9, 116.5 40.0, 116.3 40.0, 116.3 39.9))'), coordinate);

-- 计算距离
SELECT name, ST_Distance_Sphere(coordinate, ST_GeomFromText('POINT(116.3974 39.9093)')) as distance
FROM locations 
ORDER BY distance ASC;

6. 组合索引 (Composite Index)

定义与特性

在多个列上建立的索引，也称为复合索引或多列索引。

-- 创建组合索引
CREATE TABLE sales (
    sale_id INT PRIMARY KEY AUTO_INCREMENT,
    sale_date DATE,
    customer_id INT,
    product_id INT,
    quantity INT,
    amount DECIMAL(10,2),
    INDEX idx_composite (sale_date, customer_id, product_id)
);

最左前缀原则

组合索引遵循最左前缀原则，查询必须从索引的最左列开始。

-- 有效使用组合索引的查询
EXPLAIN SELECT * FROM sales WHERE sale_date = '2023-01-01';
EXPLAIN SELECT * FROM sales WHERE sale_date = '2023-01-01' AND customer_id = 100;
EXPLAIN SELECT * FROM sales WHERE sale_date = '2023-01-01' AND customer_id = 100 AND product_id = 500;

-- 无法使用索引的查询
EXPLAIN SELECT * FROM sales WHERE customer_id = 100;  -- 没有包含sale_date
EXPLAIN SELECT * FROM sales WHERE product_id = 500;   -- 没有包含前两列

索引列顺序策略

-- 好的顺序：选择性高的列在前
-- 选择性计算
SELECT 
    COUNT(DISTINCT sale_date) / COUNT(*) as selectivity_date,
    COUNT(DISTINCT customer_id) / COUNT(*) as selectivity_customer,
    COUNT(DISTINCT product_id) / COUNT(*) as selectivity_product
FROM sales;

-- 根据选择性创建最优索引
CREATE INDEX idx_optimal ON sales(sale_date, customer_id, product_id);

7. 前缀索引 (Prefix Index)

定义与特性

对字符串列的前缀部分建立索引，可以显著减少索引大小。

-- 创建前缀索引
CREATE TABLE logs (
    id INT PRIMARY KEY AUTO_INCREMENT,
    url VARCHAR(500),
    ip_address VARCHAR(45),
    INDEX idx_url_prefix (url(100)),
    INDEX idx_ip_prefix (ip_address(15))
);

确定最优前缀长度

-- 计算不同前缀长度的选择性
SELECT 
    COUNT(DISTINCT LEFT(url, 10)) / COUNT(*) as selectivity_10,
    COUNT(DISTINCT LEFT(url, 50)) / COUNT(*) as selectivity_50,
    COUNT(DISTINCT LEFT(url, 100)) / COUNT(*) as selectivity_100,
    COUNT(DISTINCT url) / COUNT(*) as full_selectivity
FROM logs;

-- 选择在可接受存储开销下选择性接近完整列的前缀长度

使用场景与限制

-- 适合长文本字段
CREATE TABLE articles (
    id INT PRIMARY KEY,
    title VARCHAR(200),
    content TEXT,
    INDEX idx_content_prefix (content(200))
);

-- 前缀索引无法用于ORDER BY和覆盖索引
EXPLAIN SELECT content FROM articles ORDER BY content;  -- 无法使用前缀索引排序

索引设计与优化策略

索引选择原则

  1. 选择性原则：选择区分度高的列建立索引
  2. 最左前缀原则：合理设计组合索引的列顺序
  3. 覆盖索引：让查询只需要访问索引而不需要访问数据行
-- 覆盖索引示例
CREATE INDEX idx_covering ON orders(customer_id, order_date, total_amount);

-- 这个查询只需要访问索引
EXPLAIN SELECT customer_id, order_date, total_amount 
FROM orders 
WHERE customer_id = 100 AND order_date >= '2023-01-01';

索引维护监控

-- 查看索引使用情况
SELECT 
    OBJECT_SCHEMA,
    OBJECT_NAME,
    INDEX_NAME,
    COUNT_READ,
    COUNT_FETCH
FROM performance_schema.table_io_waits_summary_by_index_usage
WHERE OBJECT_SCHEMA = 'your_database';

-- 识别未使用的索引
SELECT 
    s.OBJECT_SCHEMA,
    s.OBJECT_NAME,
    s.INDEX_NAME
FROM performance_schema.table_io_waits_summary_by_index_usage s
WHERE s.INDEX_NAME IS NOT NULL
AND s.COUNT_READ = 0 AND s.COUNT_FETCH = 0;

常见索引陷阱

-- 1. 过多的索引影响写性能
-- 每个INSERT/UPDATE/DELETE都需要更新所有相关索引

-- 2. 索引列上使用函数会导致索引失效
EXPLAIN SELECT * FROM users WHERE YEAR(created_at) = 2023;  -- 索引失效
EXPLAIN SELECT * FROM users WHERE created_at >= '2023-01-01' AND created_at < '2024-01-01';  -- 使用索引

-- 3. 隐式类型转换导致索引失效
CREATE TABLE users (id VARCHAR(50) PRIMARY KEY, name VARCHAR(100));
EXPLAIN SELECT * FROM users WHERE id = 123;  -- 索引失效，因为123是数字
EXPLAIN SELECT * FROM users WHERE id = '123';  -- 使用索引

总结

正确的索引设计是数据库性能优化的基石。在实际应用中，需要根据具体的查询模式、数据分布和业务需求来选择合适的索引类型和策略。记住，索引不是越多越好，而是越合适越好。定期监控索引的使用情况，删除无效索引，优化现有索引，才能保持数据库的最佳性能。

通过本文的详细解析，相信你已经对MySQL的各种索引类型有了全面的理解。在实际工作中，结合EXPLAIN分析查询执行计划，持续优化索引策略，将显著提升你的数据库应用性能。
