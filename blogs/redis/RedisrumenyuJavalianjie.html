Redis入门与Java连接：现代Java项目的缓存利器

一、Redis是什么？为什么Java项目需要它？

Redis简介

Redis（Remote Dictionary Server）是一个开源的、基于内存的键值对存储系统，它不仅仅是一个简单的缓存工具，更是一个高性能的数据结构服务器。支持字符串、哈希、列表、集合、有序集合等多种数据结构。

Java项目为什么需要Redis？

  1. 性能提升：Redis基于内存操作，读写速度极快（10万+ QPS），远超传统磁盘数据库
  2. 缓解数据库压力：将频繁访问的数据缓存在Redis中，减少对MySQL等数据库的查询
  3. 会话存储：分布式环境下存储用户会话信息
  4. 分布式锁：实现跨JVM的进程同步
  5. 消息队列：利用List或Stream实现简单的消息队列功能
  6. 实时排行榜：利用Sorted Set轻松实现排名功能
  7. 缓存雪崩/击穿/穿透的解决方案：提供完善的缓存策略

二、Redis vs Memcached vs 本地缓存

对比分析

特性RedisMemcached本地缓存（Caffeine/Guava）
数据结构丰富（5种核心）简单（Key-Value）依赖实现
持久化支持（RDB/AOF）不支持不支持
集群模式原生支持需要客户端实现不支持
内存管理可配置淘汰策略LRU算法依赖实现
事务支持支持不支持不支持
适用场景复杂缓存场景简单键值缓存单机应用

选择建议：

  • Redis：需要复杂数据结构、持久化、分布式特性的场景
  • Memcached：只需要简单键值缓存，追求极致简单性
  • 本地缓存：单机应用，数据量小，访问极其频繁

三、Java连接Redis：三大客户端对比

Jedis

// 优点：简单直接、API直观
// 缺点：线程不安全、连接池管理稍复杂

Jedis jedis = new Jedis("localhost", 6379);
jedis.set("key", "value");
String value = jedis.get("key");

Lettuce（Spring Boot 2.x+ 默认）

// 优点：支持异步、响应式编程，连接线程安全
// 缺点：API相对复杂

RedisClient client = RedisClient.create("redis://localhost:6379");
StatefulRedisConnection<String, String> connection = client.connect();
RedisCommands<String, String> commands = connection.sync();
commands.set("key", "value");

Redisson

// 优点：分布式特性丰富，API最友好
// 缺点：相对较重

Config config = new Config();
config.useSingleServer().setAddress("redis://127.0.0.1:6379");
RedissonClient redisson = Redisson.create(config);
RBucket<String> bucket = redisson.getBucket("key");
bucket.set("value");

对比总结

  • 性能：Lettuce ≈ Redisson > Jedis（在高并发下）
  • 功能丰富度：Redisson > Lettuce > Jedis
  • 易用性：Redisson > Jedis > Lettuce
  • 社区活跃度：Lettuce > Redisson > Jedis

2. 配置类

@Configuration
@EnableCaching
public class RedisConfig {
    
    @Bean
    public RedisTemplate<String, Object> redisTemplate(
            RedisConnectionFactory redisConnectionFactory) {
        
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(redisConnectionFactory);
        
        // 使用Jackson2JsonRedisSerializer序列化
        Jackson2JsonRedisSerializer<Object> serializer = 
            new Jackson2JsonRedisSerializer<>(Object.class);
        
        // 解决查询缓存转换异常的问题
        ObjectMapper om = new ObjectMapper();
        om.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        om.activateDefaultTyping(
            om.getPolymorphicTypeValidator(),
            ObjectMapper.DefaultTyping.NON_FINAL
        );
        serializer.setObjectMapper(om);
        
        // 设置key和value的序列化规则
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(serializer);
        template.setHashKeySerializer(new StringRedisSerializer());
        template.setHashValueSerializer(serializer);
        
        template.afterPropertiesSet();
        return template;
    }
    
    @Bean
    public CacheManager cacheManager(RedisConnectionFactory factory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofMinutes(10))  // 默认过期时间
            .serializeKeysWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new StringRedisSerializer()))
            .serializeValuesWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new GenericJackson2JsonRedisSerializer()))
            .disableCachingNullValues();
        
        return RedisCacheManager.builder(factory)
            .cacheDefaults(config)
            .build();
    }
}

3. 业务层使用

@Service
public class UserService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    private static final String USER_KEY_PREFIX = "user:";
    
    // 基本操作
    public void cacheUser(User user) {
        String key = USER_KEY_PREFIX + user.getId();
        redisTemplate.opsForValue().set(key, user, 30, TimeUnit.MINUTES);
    }
    
    public User getUser(Long id) {
        String key = USER_KEY_PREFIX + id;
        return (User) redisTemplate.opsForValue().get(key);
    }
    
    // Hash操作示例
    public void cacheUserInfo(User user) {
        String key = "user:hash:" + user.getId();
        Map<String, Object> map = new HashMap<>();
        map.put("name", user.getName());
        map.put("email", user.getEmail());
        map.put("age", user.getAge());
        redisTemplate.opsForHash().putAll(key, map);
        redisTemplate.expire(key, 1, TimeUnit.HOURS);
    }
    
    // 使用缓存注解
    @Cacheable(value = "users", key = "#id")
    public User findById(Long id) {
        // 数据库查询逻辑
        return userRepository.findById(id).orElse(null);
    }
    
    @CachePut(value = "users", key = "#user.id")
    public User updateUser(User user) {
        // 更新数据库
        return userRepository.save(user);
    }
    
    @CacheEvict(value = "users", key = "#id")
    public void deleteUser(Long id) {
        userRepository.deleteById(id);
    }
}

2. 连接池配置建议

关键参数优化：

@Configuration
public class RedisPoolConfig {
    
    @Bean
    public LettuceConnectionFactory redisConnectionFactory() {
        LettucePoolingClientConfiguration config = 
            LettucePoolingClientConfiguration.builder()
                .poolConfig(getPoolConfig())
                .clientOptions(getClientOptions())
                .build();
        
        RedisStandaloneConfiguration serverConfig = 
            new RedisStandaloneConfiguration("localhost", 6379);
        
        return new LettuceConnectionFactory(serverConfig, config);
    }
    
    private GenericObjectPoolConfig<?> getPoolConfig() {
        GenericObjectPoolConfig<?> poolConfig = new GenericObjectPoolConfig<>();
        
        // 核心配置（根据实际情况调整）
        poolConfig.setMaxTotal(50);           // 最大连接数
        poolConfig.setMaxIdle(20);            // 最大空闲连接
        poolConfig.setMinIdle(10);            // 最小空闲连接
        poolConfig.setMaxWaitMillis(1000);    // 获取连接最大等待时间
        
        // 健康检查配置
        poolConfig.setTestOnBorrow(true);     // 借用连接时测试
        poolConfig.setTestWhileIdle(true);    // 空闲时测试
        poolConfig.setTimeBetweenEvictionRunsMillis(30000); // 逐出扫描间隔
        
        // 逐出策略
        poolConfig.setMinEvictableIdleTimeMillis(60000); // 最小空闲时间
        poolConfig.setNumTestsPerEvictionRun(3);         // 每次检查数量
        
        return poolConfig;
    }
    
    private ClientOptions getClientOptions() {
        return ClientOptions.builder()
            .disconnectedBehavior(ClientOptions.DisconnectedBehavior.REJECT_COMMANDS)
            .autoReconnect(true)
            .requestQueueSize(100)
            .socketOptions(SocketOptions.builder()
                .connectTimeout(Duration.ofSeconds(2))
                .keepAlive(true)
                .build())
            .build();
    }
}

    // 建议配置：

4. 常见问题解决方案

  1. 连接泄露：确保每次操作后正确归还连接
  2. 连接数暴涨：合理设置max-active，使用连接池监控
  3. 超时问题：根据网络状况调整timeout，设置合理的重试策略
  4. 内存溢出：合理设置数据过期时间，监控内存使用

总结

Redis作为Java项目的缓存解决方案，提供了高性能、丰富的数据结构和良好的扩展性。在选择客户端时，Spring Boot 2.x+推荐使用Lettuce，需要丰富分布式特性时考虑Redisson。合理的连接池配置和监控是保证Redis稳定运行的关键。

记住：没有最好的配置，只有最适合的配置。根据实际业务场景、数据量和访问模式，持续监控和调整Redis配置，才能发挥其最大价值。
