设计模式的基石：面向对象设计原则（SOLID）

mingdada2025-11-06设计模式设计模式

上一篇：《【设计模式系列：开篇】我们为什么要学习设计模式?》 在软件开发中，设计模式为我们提供了解决常见问题的可重用方案。但比设计模式更重要的是其背后的设计原则，特别是SOLID原则。这些原则是构建可维护、可扩展和健壮软件系统的基石。

什么是SOLID原则？

SOLID是五个面向对象设计原则的首字母缩写，由Robert C. Martin提出：

  • S - 单一职责原则 (SRP)

一个类应该只有一个引起变化的原因

换句话说，一个类只负责一个功能领域中的相应职责。

  • O - 开闭原则 (OCP)

软件实体应该对扩展开放，对修改关闭

模块应该在不修改源代码的情况下扩展其行为。

  • L - 里氏替换原则 (LSP)

子类型必须能够替换它们的基类型

任何基类出现的地方，子类都可以替代它，而不会影响程序的正确性。

  • I - 接口隔离原则 (ISP)

不应该强迫客户端依赖于它们不使用的接口

多个特定接口优于一个通用接口。

  • D - 依赖倒置原则 (DIP)

高层模块不应该依赖于低层模块，二者都应该依赖于抽象

抽象不应该依赖于细节，细节应该依赖于抽象。

实战：重构一个违背SOLID原则的订单处理类

让我们通过一个具体的例子来看看如何应用SOLID原则。

重构前的代码（违反SOLID原则）

/**
 * 违反SOLID原则的订单处理类
 * 问题：这个类承担了太多职责，违反了多个SOLID原则
 */
public class OrderProcessor {
    
    public void processOrder(Order order) {
        // 验证订单
        if (order.getItems().isEmpty()) {
            throw new IllegalArgumentException("订单不能为空");
        }
        if (order.getCustomer() == null) {
            throw new IllegalArgumentException("客户信息不能为空");
        }
        
        // 计算总价
        double total = 0;
        for (Item item : order.getItems()) {
            total += item.getPrice() * item.getQuantity();
        }
        order.setTotalAmount(total);
        
        // 应用折扣
        if (order.getCustomer().isVIP()) {
            order.setTotalAmount(total * 0.9); // VIP客户9折
        }
        
        // 保存到数据库
        saveToDatabase(order);
        
        // 发送邮件通知
        sendEmailNotification(order);
        
        // 生成发票
        generateInvoice(order);
        
        // 更新库存
        updateInventory(order);
    }
    
    private void saveToDatabase(Order order) {
        // 数据库保存逻辑
        System.out.println("保存订单到数据库: " + order.getId());
    }
    
    private void sendEmailNotification(Order order) {
        // 发送邮件逻辑
        System.out.println("发送订单确认邮件给: " + order.getCustomer().getEmail());
    }
    
    private void generateInvoice(Order order) {
        // 生成发票逻辑
        System.out.println("生成发票: " + order.getId());
    }
    
    private void updateInventory(Order order) {
        // 更新库存逻辑
        System.out.println("更新库存");
    }
}

问题分析

上面的OrderProcessor类违反了多个SOLID原则：

1.违反单一职责原则：一个类承担了订单验证、价格计算、数据库操作、邮件发送、发票生成、库存更新等多个职责

2.违反开闭原则：如果要添加新的折扣策略或通知方式，需要修改现有代码

3.违反接口隔离原则：没有使用接口，所有方法都耦合在一起

4.违反依赖倒置原则：直接依赖于具体实现，没有使用抽象

重构后的代码（遵循SOLID原则）

// 定义核心接口 - 遵循接口隔离原则

/**
 * 订单验证接口
 */
public interface OrderValidator {
    boolean validate(Order order);
}

/**
 * 价格计算接口
 */
public interface PriceCalculator {
    double calculateTotal(Order order);
}

/**
 * 订单持久化接口
 */
public interface OrderRepository {
    void save(Order order);
}

/**
 * 通知服务接口
 */
public interface NotificationService {
    void sendNotification(Order order);
}

/**
 * 库存服务接口
 */
public interface InventoryService {
    void updateInventory(Order order);
}

// 具体实现类

/**
 * 基本订单验证 - 遵循单一职责原则
 */
public class BasicOrderValidator implements OrderValidator {
    @Override
    public boolean validate(Order order) {
        if (order.getItems().isEmpty()) {
            throw new IllegalArgumentException("订单不能为空");
        }
        if (order.getCustomer() == null) {
            throw new IllegalArgumentException("客户信息不能为空");
        }
        return true;
    }
}

/**
 * 折扣价格计算器 - 遵循开闭原则（易于扩展新的折扣策略）
 */
public class DiscountPriceCalculator implements PriceCalculator {
    private List<DiscountStrategy> discountStrategies;
    
    public DiscountPriceCalculator(List<DiscountStrategy> discountStrategies) {
        this.discountStrategies = discountStrategies;
    }
    
    @Override
    public double calculateTotal(Order order) {
        double total = order.getItems().stream()
                .mapToDouble(item -> item.getPrice() * item.getQuantity())
                .sum();
        
        // 应用所有适用的折扣策略
        for (DiscountStrategy strategy : discountStrategies) {
            total = strategy.applyDiscount(order, total);
        }
        
        return total;
    }
}

/**
 * 折扣策略接口 - 支持多种折扣策略
 */
public interface DiscountStrategy {
    double applyDiscount(Order order, double total);
}

/**
 * VIP折扣策略
 */
public class VIPDiscountStrategy implements DiscountStrategy {
    @Override
    public double applyDiscount(Order order, double total) {
        if (order.getCustomer().isVIP()) {
            return total * 0.9; // VIP客户9折
        }
        return total;
    }
}

/**
 * 满减折扣策略 - 易于扩展新的折扣类型
 */
public class BulkPurchaseDiscountStrategy implements DiscountStrategy {
    @Override
    public double applyDiscount(Order order, double total) {
        if (total > 1000) {
            return total * 0.95; // 满1000打95折
        }
        return total;
    }
}

/**
 * 数据库订单存储
 */
public class DatabaseOrderRepository implements OrderRepository {
    @Override
    public void save(Order order) {
        System.out.println("保存订单到数据库: " + order.getId());

    @Override

}

 * 库存服务

public class DefaultInventoryService implements InventoryService {

// 重构后的订单处理器 - 遵循依赖倒置原则
public class RefactoredOrderProcessor {
    private final OrderValidator validator;
    private final PriceCalculator priceCalculator;
    private final OrderRepository repository;
    private final NotificationService notificationService;
    private final InventoryService inventoryService;
    
    // 依赖注入 - 依赖于抽象而非具体实现
    public RefactoredOrderProcessor(OrderValidator validator,
                                  PriceCalculator priceCalculator,
                                  OrderRepository repository,
                                  NotificationService notificationService,
                                  InventoryService inventoryService) {
        this.validator = validator;
        this.priceCalculator = priceCalculator;
        this.repository = repository;
        this.notificationService = notificationService;
        this.inventoryService = inventoryService;
    }
    
    public void processOrder(Order order) {
        // 验证订单
        validator.validate(order);
        
        // 计算价格
        double total = priceCalculator.calculateTotal(order);
        order.setTotalAmount(total);
        
        // 保存订单
        repository.save(order);
        
        // 发送通知
        notificationService.sendNotification(order);
        
        // 更新库存
        inventoryService.updateInventory(order);
    }
}

// 发票生成器 - 分离出来的新职责
public class InvoiceGenerator {
    public void generateInvoice(Order order) {
        System.out.println("生成发票: " + order.getId());
    }
}

使用示例

public class OrderProcessingDemo {
    public static void main(String[] args) {
        // 创建折扣策略
        List<DiscountStrategy> discountStrategies = Arrays.asList(
            new VIPDiscountStrategy(),
            new BulkPurchaseDiscountStrategy()
        );
        
        // 创建订单处理器（依赖注入）
        RefactoredOrderProcessor processor = new RefactoredOrderProcessor(
            new BasicOrderValidator(),
            new DiscountPriceCalculator(discountStrategies),
            new DatabaseOrderRepository(),
            new EmailNotificationService(),
            new DefaultInventoryService()
        );
        
        // 创建测试数据
        Customer customer = new Customer("张三", "zhangsan@example.com", true);
        List<Item> items = Arrays.asList(
            new Item("笔记本电脑", 5000, 1),
            new Item("鼠标", 100, 2)
        );
        Order order = new Order("ORDER001", customer, items);
        
        // 处理订单
        processor.processOrder(order);
    }
}

重构带来的好处

1.单一职责原则：

  • 每个类都有明确的单一职责

  • 代码更易于理解和维护

2.开闭原则：

  • 可以轻松添加新的折扣策略（实现DiscountStrategy接口）

  • 可以添加新的验证规则或通知方式而不修改现有代码

3.里氏替换原则：

  • 所有实现都可以被其接口替换

  • 提高了代码的灵活性和可测试性

4.接口隔离原则：

  • 每个接口都有明确的单一功能

  • 客户端只依赖于它们实际使用的接口

5.依赖倒置原则：

  • 高层模块不依赖于低层模块的具体实现

  • 便于单元测试和模块替换

总结

SOLID原则不是死板的规则，而是指导我们编写高质量代码的指南。通过遵循这些原则，我们可以创建出：

  • ✅ 更易维护的代码

  • ✅ 更易扩展的系统

  • ✅ 更易测试的组件

  • ✅ 更少耦合的模块

  • ✅ 更高复用的代码

记住，原则的目的是服务于实践，而不是束缚开发。在实际项目中，需要根据具体情况灵活应用这些原则，在过度设计和设计不足之间找到平衡点。

优秀的软件设计不是一次性完成的，而是通过持续重构和改进逐渐形成的。
