1. 设计模式简介

在软件开发中，我们经常会遇到对象创建的问题。传统的new关键字虽然简单直接，但随着系统复杂度增加，直接使用new会导致代码耦合度高、难以扩展和维护。工厂方法模式应运而生，它提供了一种更优雅的对象创建方式。

工厂方法模式是一种创建型设计模式，它将对象的实例化推迟到子类，让子类决定实例化哪个类。这种模式在Java生态中广泛应用，比如Spring的BeanFactory、日志框架的LoggerFactory等都是工厂方法模式的典型实现。

2. 工厂方法模式概述

核心思想：告别new，拥抱工厂 解决的问题：

解耦对象创建与使用：客户端不需要知道具体产品的创建细节

提高扩展性：新增产品类型时无需修改现有代码

统一创建逻辑：将复杂的创建过程封装在工厂中

支持产品族扩展：易于扩展新的产品系列

模式结构

客户端 → 抽象工厂 → 具体工厂
                ↓
           抽象产品 → 具体产品

3. 四个核心角色详解

3.1 抽象产品（Abstract Product）

抽象产品定义了产品的接口，是所有具体产品类的父类或实现的接口。它规定了产品应该具有的基本操作。

/**
 * 抽象产品：Logger接口
 * 定义了日志记录器应该具备的基本功能
 */
public interface Logger {
    void debug(String message);
    void info(String message);
    void warn(String message);
    void error(String message);
    boolean isDebugEnabled();
    boolean isInfoEnabled();
}

3.2 具体产品（Concrete Product）

具体产品实现了抽象产品接口，是工厂方法模式中真正被创建的对象。

/**
 * 具体产品：控制台日志记录器
 * 将日志输出到控制台
 */
public class ConsoleLogger implements Logger {
    private final String name;
    private LogLevel level = LogLevel.INFO;
    
    public ConsoleLogger(String name) {
        this.name = name;
    }
    
    public ConsoleLogger(String name, LogLevel level) {
        this.name = name;
        this.level = level;
    }
    
    @Override
    public void debug(String message) {
        if (level.ordinal() <= LogLevel.DEBUG.ordinal()) {
            System.out.println("[DEBUG] " + formatMessage(message));
        }
    }
    
    @Override
    public void info(String message) {
        if (level.ordinal() <= LogLevel.INFO.ordinal()) {
            System.out.println("[INFO]  " + formatMessage(message));
        }
    }
    
    @Override
    public void warn(String message) {
        if (level.ordinal() <= LogLevel.WARN.ordinal()) {
            System.out.println("[WARN]  " + formatMessage(message));
        }
    }
    
    @Override
    public void error(String message) {
        if (level.ordinal() <= LogLevel.ERROR.ordinal()) {
            System.out.println("[ERROR] " + formatMessage(message));
        }
    }
    
    @Override
    public boolean isDebugEnabled() {
        return level.ordinal() <= LogLevel.DEBUG.ordinal();
    }
    
    @Override
    public boolean isInfoEnabled() {
        return level.ordinal() <= LogLevel.INFO.ordinal();
    }
    
    private String formatMessage(String message) {
        return String.format("%s - %s - %s", 
            LocalDateTime.now().format(DateTimeFormatter.ISO_LOCAL_DATE_TIME),
            name, 
            message);
    }
}

/**
 * 具体产品：文件日志记录器
 * 将日志写入文件（这里用控制台模拟文件输出）
 */
public class FileLogger implements Logger {
    private final String name;
    private final String filePath;
    
    public FileLogger(String name) {
        this.name = name;
        this.filePath = "logs/application.log";
    }
    
    public FileLogger(String name, String filePath) {
        this.name = name;
        this.filePath = filePath;
    }
    
    @Override
    public void debug(String message) {
        writeToFile("[DEBUG] " + message);
    }
    
    @Override
    public void info(String message) {
        writeToFile("[INFO]  " + message);
    }
    
    @Override
    public void warn(String message) {
        writeToFile("[WARN]  " + message);
    }
    
    @Override
    public void error(String message) {
        writeToFile("[ERROR] " + message);
    }
    
    @Override
    public boolean isDebugEnabled() {
        return true;
    }
    
    @Override
    public boolean isInfoEnabled() {
        return true;
    }
    
    private void writeToFile(String logEntry) {
        // 模拟写入文件操作
        String formattedEntry = String.format("%s - %s - %s%n", 
            LocalDateTime.now().format(DateTimeFormatter.ISO_LOCAL_DATE_TIME),
            name, 
            logEntry);
        System.out.print("写入文件[" + filePath + "]: " + formattedEntry);
    }
}

/**
 * 日志级别枚举
 */
public enum LogLevel {
    DEBUG, INFO, WARN, ERROR
}

3.3 抽象工厂（Abstract Factory）

抽象工厂声明了工厂方法，该方法返回一个抽象产品类型的对象。

/**
 * 抽象工厂：LoggerFactory
 * 定义了创建Logger对象的工厂方法
 */
public abstract class LoggerFactory {
    
    /**
     * 工厂方法 - 由子类实现具体的创建逻辑
     * @param name Logger的名称，通常是类名
     * @return Logger实例
     */
    public abstract Logger createLogger(String name);
    
    /**
     * 重载方法：通过Class对象创建Logger
     * @param clazz 类对象
     * @return Logger实例
     */
    public Logger createLogger(Class<?> clazz) {
        return createLogger(clazz.getName());
    }
    
    /**
     * 模板方法：提供默认的创建后处理
     * @param name Logger名称
     * @return 配置好的Logger实例
     */
    public Logger getLogger(String name) {
        Logger logger = createLogger(name);
        // 这里可以添加一些公共的初始化逻辑
        initializeLogger(logger);
        return logger;
    }
    
    protected void initializeLogger(Logger logger) {
        // 子类可以重写此方法进行特殊的初始化
    }
}

3.4 具体工厂（Concrete Factory）

具体工厂实现了工厂方法，返回具体产品的实例。

/**
 * 具体工厂：控制台日志工厂
 * 创建ConsoleLogger实例
 */
public class ConsoleLoggerFactory extends LoggerFactory {
    private LogLevel defaultLevel = LogLevel.INFO;
    
    public ConsoleLoggerFactory() {}
    
    public ConsoleLoggerFactory(LogLevel level) {
        this.defaultLevel = level;
    }
    
    @Override
    public Logger createLogger(String name) {
        return new ConsoleLogger(name, defaultLevel);
    }
}

/**
 * 具体工厂：文件日志工厂
 * 创建FileLogger实例
 */
public class FileLoggerFactory extends LoggerFactory {
    private final String filePath;
    
    public FileLoggerFactory() {
        this("logs/application.log");
    }
    
    public FileLoggerFactory(String filePath) {
        this.filePath = filePath;
    }
    
    @Override
    public Logger createLogger(String name) {
        return new FileLogger(name, filePath);
    }
}

/**
 * 具体工厂：网络日志工厂
 * 创建NetworkLogger实例（扩展示例）
 */
public class NetworkLoggerFactory extends LoggerFactory {
    private final String serverUrl;
    
    public NetworkLoggerFactory(String serverUrl) {
        this.serverUrl = serverUrl;
    }
    
    @Override
    public Logger createLogger(String name) {
        return new NetworkLogger(name, serverUrl);
    }
}

4. 实战：模拟日志框架

4.1 基础实现

我们已经完成了工厂方法模式的基础实现，现在来看如何使用：

/**
 * 客户端使用示例
 */
public class LoggerClient {
    public static void main(String[] args) {
        // 使用控制台日志工厂
        LoggerFactory consoleFactory = new ConsoleLoggerFactory(LogLevel.DEBUG);
        Logger consoleLogger = consoleFactory.getLogger(LoggerClient.class);
        
        consoleLogger.debug("这是一条调试信息");
        consoleLogger.info("这是一条普通信息");
        consoleLogger.warn("这是一条警告信息");
        consoleLogger.error("这是一条错误信息");
        
        System.out.println("--- 分割线 ---");
        
        // 使用文件日志工厂
        LoggerFactory fileFactory = new FileLoggerFactory("logs/myapp.log");
        Logger fileLogger = fileFactory.getLogger("com.example.MyService");
        
        fileLogger.info("服务启动成功");
        fileLogger.error("数据库连接失败");
    }
}

4.2 高级功能：配置化工厂

在实际的日志框架中，我们通常需要根据配置来创建不同的Logger：

/**
 * 配置类
 */
public class LoggerConfig {
    private final String type; // "console", "file", "network"
    private final LogLevel level;
    private final String filePath;
    private final String serverUrl;
    
    // 构造器、Getter方法等...
    public LoggerConfig(String type, LogLevel level, String filePath, String serverUrl) {
        this.type = type;
        this.level = level;
        this.filePath = filePath;
        this.serverUrl = serverUrl;
    }
    
    // Getter methods...
    public String getType() { return type; }
    public LogLevel getLevel() { return level; }
    public String getFilePath() { return filePath; }
    public String getServerUrl() { return serverUrl; }
}

/**
 * 配置化日志工厂
 * 根据配置动态创建不同类型的Logger
 */
public class ConfigurableLoggerFactory extends LoggerFactory {
    private final LoggerConfig config;
    
    public ConfigurableLoggerFactory(LoggerConfig config) {
        this.config = config;
    }
    
    @Override
    public Logger createLogger(String name) {
        switch (config.getType().toLowerCase()) {
            case "file":
                return new FileLogger(name, config.getFilePath());
            case "network":
                return new NetworkLogger(name, config.getServerUrl());
            case "console":
            default:
                return new ConsoleLogger(name, config.getLevel());
        }
    }
}

4.3 装饰器模式增强

为了支持更灵活的日志功能，我们可以结合装饰器模式：

/**
 * 日志装饰器：支持异步日志
 */
public class AsyncLogger implements Logger {
    private final Logger delegate;
    private final ExecutorService executor;
    
    public AsyncLogger(Logger delegate) {
        this.delegate = delegate;
        this.executor = Executors.newSingleThreadExecutor();
    }
    
    @Override
    public void debug(String message) {
        executor.submit(() -> delegate.debug(message));
    }
    
    @Override
    public void info(String message) {
        executor.submit(() -> delegate.info(message));
    }
    
    @Override
    public void warn(String message) {
        executor.submit(() -> delegate.warn(message));
    }
    
    @Override
    public void error(String message) {
        executor.submit(() -> delegate.error(message));
    }
    
    @Override
    public boolean isDebugEnabled() {
        return delegate.isDebugEnabled();
    }
    
    @Override
    public boolean isInfoEnabled() {
        return delegate.isInfoEnabled();
    }
    
    public void shutdown() {
        executor.shutdown();
    }
}

/**
 * 支持异步的日志工厂
 */
public class AsyncLoggerFactory extends LoggerFactory {
    private final LoggerFactory delegateFactory;
    
    public AsyncLoggerFactory(LoggerFactory delegateFactory) {
        this.delegateFactory = delegateFactory;
    }
    
    @Override
    public Logger createLogger(String name) {
        Logger baseLogger = delegateFactory.createLogger(name);
        return new AsyncLogger(baseLogger);
    }
}

4.4 完整使用示例

/**
 * 完整的日志框架使用示例
 */
public class CompleteLoggerDemo {
    public static void main(String[] args) {
        // 1. 基础使用
        System.out.println("=== 基础使用 ===");
        LoggerFactory basicFactory = new ConsoleLoggerFactory(LogLevel.DEBUG);
        Logger basicLogger = basicFactory.getLogger(CompleteLoggerDemo.class);
        basicLogger.info("基础日志功能测试");
        
        // 2. 配置化使用
        System.out.println("\n=== 配置化使用 ===");
        LoggerConfig config = new LoggerConfig("file", LogLevel.WARN, "logs/app.log", null);
        LoggerFactory configFactory = new ConfigurableLoggerFactory(config);
        Logger configLogger = configFactory.getLogger("AppConfig");
        configLogger.debug("这条DEBUG日志不会被输出"); // 级别不够
        configLogger.warn("这条WARN日志会被输出到文件");
        
        // 3. 异步日志
        System.out.println("\n=== 异步日志 ===");
        LoggerFactory asyncFactory = new AsyncLoggerFactory(new ConsoleLoggerFactory());
        Logger asyncLogger = asyncFactory.getLogger("AsyncService");
        asyncLogger.info("异步日志测试");
        
        // 4. 模拟真实业务场景
        System.out.println("\n=== 业务场景模拟 ===");
        UserService userService = new UserService();
        userService.registerUser("张三");
        userService.login("张三", "password");
    }
}

/**
 * 业务服务类，使用日志框架
 */
class UserService {
    private final Logger logger;
    
    public UserService() {
        // 在实际框架中，这里通常会通过依赖注入获取Logger
        LoggerFactory factory = new ConsoleLoggerFactory(LogLevel.INFO);
        this.logger = factory.getLogger(UserService.class);
    }
    
    public void registerUser(String username) {
        logger.info("开始注册用户: " + username);
        // 模拟业务逻辑
        try {
            Thread.sleep(100);
            logger.info("用户注册成功: " + username);
        } catch (InterruptedException e) {
            logger.error("用户注册失败: " + username, e);
        }
    }
    
    public void login(String username, String password) {
        logger.debug("用户登录尝试: " + username);
        // 模拟登录逻辑
        if ("password".equals(password)) {
            logger.info("用户登录成功: " + username);
        } else {
            logger.warn("用户登录失败: " + username);
        }
    }
}

5. 模式优势分析

5.1 符合开闭原则

当需要新增一种日志类型时（如数据库日志），我们只需要：

创建新的具体产品类 DatabaseLogger

创建新的具体工厂类 DatabaseLoggerFactory

无需修改任何现有代码

5.2 降低耦合度

客户端代码只依赖于抽象接口：

// 客户端只关心抽象接口
LoggerFactory factory = getLoggerFactory(); // 具体工厂通过配置决定
Logger logger = factory.getLogger(MyClass.class);
logger.info("业务日志");

5.3 单一职责原则

工厂类负责对象创建

产品类负责业务功能

配置类负责配置管理

5.4 易于测试和维护

// 测试时可以使用Mock工厂
class TestLoggerFactory extends LoggerFactory {
    private List<String> logs = new ArrayList<>();
    
    @Override
    public Logger createLogger(String name) {
        return new TestLogger(name, logs);
    }
    
    public List<String> getLogs() { return logs; }
}

6. 总结

工厂方法模式通过以下方式提升了我们的代码质量：

灵活性：轻松切换不同的Logger实现

可扩展性：新增Logger类型无需修改现有代码

可维护性：创建逻辑集中管理，便于维护

可测试性：易于模拟和测试

在实际的Logback、Log4j2等日志框架中，工厂方法模式被广泛应用。通过本文的实战示例，我们不仅理解了工厂方法模式的四个核心角色，还掌握了如何在实际项目中应用这一模式。

拥抱工厂方法，告别硬编码的new，让我们的代码更加灵活和健壮！
